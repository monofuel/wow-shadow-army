# One-bot live quest debugging — 2026-08-16

Ticket `../tickets/open/0065-quest-accept-scouting.md` (opened mid-session);
continues `quest-qa-2026-08-15.md` / ticket 0057. Question on the table: the
0057 fixes shipped, but ~10 of 15 fresh bots had ZERO quest rows after an
evening — why do bots never *accept*?

Method — the debug-port dogfood: one roster bot rolled at random
(**Kargalgan**, undead warlock, guid 1000015), launched with
`make seat-start SEAT=Kargalgan SEAT_USER=shadow7 SEAT_CLASS=warlock
SEAT_DEBUG_PORT=7801 HOME_DEBUG_PORT_BASE=7801`, then every diagnosis and fix
delivered live over `127.0.0.1:7801` — telemetry probes edited into
`accelerated.lua`, `make test-lua`, `POST /lua/reload`, read the answer off
the seat's own log ring. Seven reloads, zero seat restarts, until a client
wedge (below) forced one.

## What the probes showed, in order

1. **The world is markerless.** `probe units=86 markers=0` while a quest
   starter stood 108yd away: quest markers only arrive via
   `SMSG_QUESTGIVER_STATUS`, the server only sends it when queried, and the
   nim player runtime never sends `CMSG_QUESTGIVER_STATUS_QUERY` (only viewer
   sessions carry that verb). The stock client queries per unit entering view
   — that is what `!` is. Markers CAN be synthesized client-side, but only
   from an already-open gossip/greeting dialog. Chicken-and-egg for a bot
   whose only interaction trigger was a marker.
2. **The accept gate never opened anyway.** `allowAccept` required
   `not nearbyHunt`; starter zones are mobs wall-to-wall (`hunt=<mob>` on
   every probe line). Same trap 0057's Failure 2 removed from turn-ins.
3. **Quest travel was starved to zero ticks.** The travel probe never fired:
   `combat_kill_events` is rebuilt every frame from the retained combat-log
   ring, so `note_kills` re-armed the newest corpse every tick and reset the
   loot clock — the wall-clock cap could never expire. The live seat sat
   pinned pressing one `loot-money:` slot ("loot window open", same
   reference, hundreds of lines). loot_step runs ahead of quest travel, so
   quest_step literally never ran.
4. **Routing cannot serve town.** With scouting live, pursuits stalled at
   `nav_progress=unavailable` (navmesh gaps, ticket 0048), position frozen.

## Fixes (all Lua, all behind QUESTS, all hot-swapped via /lua/reload)

- **Loot dedupe** — `lootSeen` set (bounded 256): a corpse arms once. The
  replayed-kill-line pin is dead; the 18s cap works again.
- **Idle-log override** — an idle log (empty, or every objective complete)
  overrides the nearby-hunt gate for accepts, hub walks and scouting;
  grinding with an idle log is wasted XP. Busy log keeps the 2026-08-10 A/B
  behaviour exactly.
- **Scouting (quest_step rank 2)** — idle log + no marker anywhere: walk to
  the nearest non-exhausted friendly NPC and interact; the dialog synthesizes
  the real marker, `remember_hubs` banks the location, empty gossip/greeting
  exhausts the NPC ("ask around town"). Empty greetings now exhaust via
  `quest_frame.npc_guid`.
- **Local-steer fallback** — pursuit beyond 8yd with routing `unavailable`
  takes a bounded `local_steer` leg at the giver (the mode roam/unstick
  already trust), interacts once the last yards are trivial.

Observed live: scout walked the seat ~150yd from an open-field grind spot
into Deathknell proper, NPC to NPC (Dannal Stern -> Deathguards -> David
Trias -> town), `markers=3` and `hubs=3` appeared, and rank-1 `questgiver`
pursuits fired for Venya Marthand / Novice Elreth — the first
marker-driven giver pursuits any home bot has run from a cold spawn.

## Debug-port field notes (dogfood verdict)

- The loop works: edit -> test-lua -> `POST /lua/reload` -> read
  `status.logs` / launcher.log. Seven reloads with state carried live.
  Boot errors would return in the ack; transactionality held.
- Friction: one reload ack came back `{"ok":false}` with empty fields on a
  healthy seat (transient; immediate retry succeeded). `status.json`'s
  `logs` ring was empty over HTTP in this build — wow.log lines were read
  from launcher.log instead.
- `seat_timeout` on a wedged seat is itself diagnostic: control poll on the
  decide thread means a dead port == a dead decide loop.
