#### Gotcha: the asset token gate is not the attach slot

`game/config.py:1253` — `slot_token_valid` is literally
`config.tokens[slot] == token`, and the local realm ships exactly one token
(`tokens: ['token-0']`). So **only slot 0 authenticates for assets/navmesh
HTTP**, while the attach slot is whatever seat we are (2-5). Sending the attach
slot in the asset query gets a 403, the client falls back to a local DBC dir,
`chrraces.dbc` is missing, and the session dies with the very misleading
`Character race must be a playable Vanilla race.`

Fixed by decoupling the two: `--asset-slot` (default 0) in both `army_host` and
`env_smoke` now feeds the assets/navmesh query, independent of `--slot`.

Second gotcha: the env host **caches resource state across attaches**. Once a
bad attach poisons the DBC load, every later attach fails the same way even
after the URL is fixed. Restart the host (`tools/env_host.sh stop && start`)
after correcting anything asset-related.
