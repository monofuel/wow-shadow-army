### Phase B — launch layer rewiring (mechanical, blocks any multi-seat run)

The army make targets still speak the dead protocol's language. As written,
`make escort-army` would fire four seats at the **same** account looking for
characters `Slot2`–`Slot5` that do not exist.

- [ ] Drop `--goal-id=…` from `army-host`, `escort`, `escort-army-nim`,
      `grind-army-nim`, `grind`. The host accepts and discards it.
- [ ] Thread per-seat credentials into every army target. `army_host` defaults to
      `coworld`/`coworld` (`army_host.nim:26-27`) and character `Slot<N>`
      (`army_host.nim:674-676`) — neither is right for a seat. The values already
      exist in the Makefile from the old seat era:

      | slot | character  | account   | pass      | Makefile |
      |------|------------|-----------|-----------|----------|
      | 2    | Shadowfel  | shadow1   | shadow1   | 480-482  |
      | 3    | Igris      | shadow2   | shadow2   | 650-652  |
      | 4    | Tusk       | shadow3   | shadow3   | 739-741  |
      | 5    | Beru       | shadow4   | shadow4   | 799-801  |

- [ ] Decide how the per-slot map is expressed (a `SEAT_<n>_*` block, or a small
      lookup the targets index by `$$s`) — the current loop `for s in 2 3 4 5`

- [ ] Verify each of the four accounts still exists on the realm before relying
      on the map (the `*-account` targets are idempotent if not).

Note `character_creation` is hardcoded `nil` (`army_host.nim:693`), so attach can
only bind an **existing** character. That is fine today — all five are present —
but a brand-new seat needs either the old fork wire-create path or that field
filled in.
